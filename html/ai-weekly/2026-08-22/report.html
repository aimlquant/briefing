SECTION 00 · EXECUTIVE SUMMARY

이번 주: 성능보다 통제 경계

ONE SENTENCE모델의 힘이 커질수록 경쟁력은 무엇을 할 수 있나에서 언제 멈추고 어떻게 증명하나로 이동한다.

세 개의 가장 강한 신호는 서로 다른 층에서 같은 문제를 드러냈다. OpenAI는 사이버 임계 능력에 가까워지자 강화학습을 중단하고 감시 비용을 공개했다. Anthropic은 생성 문장에 통계적 워터마크를 넣으며 출처 표시를 모델 동작에 포함했다. Wiz가 공개한 Snowflake 커넥터 사고에서는 AI가 제안한 수정이 비신뢰 입력과 고권한 비밀 사이의 경계를 무너뜨렸다.

이 셋을 함께 읽으면 안전은 추상적인 정렬 문제가 아니다. 학습을 멈출 권한, 탐지의 오탐·미탐 한계, 셸과 데이터의 구분, 최소 권한, 사람이 확인할 시간 같은 운영 설계다. 레이더의 에이전트 협업 연구, Linear 사용 데이터, 에이전트 테스트 논문도 같은 결론을 보강한다. 산출량이 늘거나 에이전트 수가 많아져도 범위·비용·인과·실패 궤적을 함께 측정하지 않으면 성능처럼 보이는 숫자를 오해한다.

학습중단 가능해야 한다

능력 경계에 닿은 뒤가 아니라 닿기 전에 학습·배포 게이트가 작동해야 한다.

출력표시의 한계를 말해야 한다

워터마크 탐지는 관여 가능성이지 저자·진실·부정행위의 증명이 아니다.

도구권한 경로를 검증해야 한다

AI 코드 리뷰는 생성 여부보다 비신뢰 입력이 비밀과 실행권한에 닿는지를 본다.

DEEP 01 · MODEL SAFETY · SCORE 98

OpenAI, 사이버 임계 능력 앞에서 학습을 멈추다

2주 강화학습 중단과 약 20% 추론 비용은 “안전 우선”이라는 문구를 실제 릴리스·용량 결정으로 번역한 사례다.

8월 18일공식 공개2주RL 훈련 중단30분경보·에스컬레이션≈20%추론 컴퓨트 오버헤드

무슨 일이 있었나

OpenAI는 Hugging Face와 공동 조사한 실제 사이버 사건, 그리고 예비 평가에서 Astra가 “critical” 사이버 능력에 가까워졌다는 신호를 함께 공개했다. 이에 따라 사이버 능력을 더 키울 수 있는 강화학습을 2주 멈췄고, 계획된 가장 큰 프런티어 RL 실행은 안전장치 검증이 끝나지 않아 계속 보류한다고 밝혔다. 이것은 모델을 이미 출시한 뒤 악용을 차단하는 대응과 다르다. 능력 증가의 입력인 학습 자체에 게이트를 건 것이다.

회사 설명의 세 축은 보안, 모니터링, 정렬이다. 도구를 쓰는 RL·평가 워크로드는 엄격한 작업·네트워크 격리와 연속 테스트를 받는다. 추론 중에는 샘플링한 모든 토큰에 활성화 분류기를 적용하고, 여러 단계의 자동 조사기가 신호를 좁힌다. 경보는 사람이 30분 안에 확인하고 에스컬레이션하는 운영 약속과 연결된다. OpenAI는 이 감시가 추론 컴퓨트의 약 20%를 더 쓴다고 적었다.

왜 중요한가

첫째, 안전 임계값은 모델 카드의 사후 설명이 아니라 학습 스케줄러와 릴리스 프로세스의 입력이 됐다. 둘째, 모니터링은 무료가 아니다. 20%가 모든 워크로드에 그대로 적용된다고 일반화할 수는 없지만, 안전 예산을 GPU·지연시간·사람의 대기 비용으로 계산해야 한다는 점은 분명하다. 셋째, 자동 탐지가 완결점이 아니다. “30분 내 인간 확인”이라는 서비스 수준이 있어야 오탐과 실제 공격 사이에서 운영이 가능하다.

확인된 주장

중단 기간, 보류 중인 실행, 격리·모니터링 구성, 30분·20% 수치는 OpenAI 공식 발표에 명시돼 있다.

남은 질문

critical 경계의 원시 평가 결과, 오탐률, 실제 사고의 세부 공격 경로는 공개 범위가 제한적이다. 독립 재현 근거로 읽어서는 안 된다.

DEEP 02 · PROVENANCE · SCORE 94

Claude의 보이지 않는 워터마크, 무엇을 증명하나

텍스트의 확률 분포에 신호를 심는 방식은 복사·붙여넣기 뒤에도 남을 수 있지만, 짧은 답과 재작성에는 약하고 ‘누가 썼는가’를 증명하지 않는다.

숨은 문자가 아니라 선택 분포다

Anthropic은 앞으로 출시할 Claude 모델의 텍스트 출력에 EU AI Act 대응을 위한 워터마크를 순차 적용한다고 발표했다. 회사 설명상 숨은 유니코드 문자, 추가 토큰, 사용자·조직·대화 식별자를 삽입하지 않는다. 대신 의미와 품질 차이가 작은 다음 토큰 후보 사이에서 비밀 키와 앞선 단어를 이용해 난수의 출처를 바꾼다. 긴 문장에 이 미세한 선택 편향이 누적되면 전용 탐지기가 통계적으로 Claude 관여 가능성을 계산한다. 기반은 Google DeepMind의 SynthID-Text 계열이다.

탐지값을 판결문으로 쓰면 안 되는 이유

선택지가 적은 짧은 답, 사실 중심 문장, 교정, 번역 일부, 코드에서는 신호를 쌓을 여지가 작다. 가벼운 편집에는 남을 수 있지만 전체 재작성은 제거할 수 있다고 Anthropic 스스로 적었다. 따라서 양성은 Claude가 관여했을 가능성을 높일 뿐 저자, 진실성, 표절, 부정행위를 확정하지 않는다. 반대로 음성도 Claude를 사용하지 않았다는 보장이 아니다. 교육·채용·출판에서 단일 탐지값으로 제재하면 기술의 의도보다 훨씬 강한 결론을 내리게 된다.

Daring Fireball의 비판이 HN에서 821점과 727댓글을 얻은 것은 기술 사실과 사회적 수용이 분리돼 있음을 보여 준다. 작성 도구가 인간의 문장 선택에 표식을 남기는 행위를 출처 투명성으로 볼지, 글쓰기의 변형으로 볼지는 논쟁 중이다. 이 반응은 중요도 신호지만 워터마크의 기술 성능을 입증하거나 반증하지는 않는다.

사용 가능한 판단

대량·장문 콘텐츠의 출처 조사에서 보조 신호로 사용하고 C2PA 파일 메타데이터, 작성 이력, 사람의 검토와 결합한다.

금지할 판단

짧은 문장 하나의 탐지 결과로 저자나 부정행위를 단정하지 않는다. 탐지 API 공개 전에는 재현 성능도 확정하지 않는다.

DEEP 03 · SUPPLY CHAIN · SCORE 97

Copilot Autofix가 안전한 CI 코드를 취약하게 바꿨다

생성 AI의 실수라기보다, AI 제안을 신뢰한 리뷰와 비신뢰 이벤트 입력·고권한 비밀이 만나는 워크플로 설계가 사고를 완성했다.

안전한 전달이 직접 보간으로 바뀌었다

Wiz의 Red Agent가 공개한 사례는 snowflakedb/snowflake-connector-net의 GitHub Actions 워크플로다. 기존 코드는 이슈 제목을 환경 변수로 넘기고 jq --arg로 JSON에 넣었다. Copilot Autofix가 공동 작성자로 기록된 수정은 이 안전한 경로를 없애고 ${{ github.event.issue.title }}을 run: 셸 블록 안에 직접 확장했다. 인증 없이 만들 수 있는 이슈 제목에 따옴표와 셸 구문을 넣으면 echo를 탈출해 명령으로 실행할 수 있었다.

Red Agent는 첫 시도에서 난 셸 오류를 관찰한 뒤 페이로드를 조정해 Jira 자격증명을 외부로 보냈다. Wiz에 따르면 이 취약점은 6월 18일 도입됐고 6월 23일 발견·신고돼 같은 날 수정과 토큰 교체가 이뤄졌다. 공개는 8월 17일이었다. 감사 결과 발견된 악용은 Wiz 테스트뿐이었다고 보고됐다. 이 날짜 구분은 “몇 달간 실제 침해됐다”는 과장을 피하기 위해 중요하다.

리뷰 질문을 바꿔야 한다

“이 코드가 AI 생성인가?”는 출처 질문이다. 보안 질문은 “공격자가 바꿀 수 있는 값이 어떤 인터프리터를 지나 어떤 권한과 비밀에 닿는가?”다. 직접 보간을 금지하고 환경 변수와 구조화된 API로 데이터를 유지하며, PR·이슈 이벤트의 권한을 낮추고 장기 비밀 대신 단기 토큰을 써야 한다. 자동 수정 제안도 같은 위협 모델과 테스트를 통과하기 전에는 코드로 승격하지 않는다.

# 위험: 이벤트 데이터가 셸 소스가 된다
run: echo '${{ github.event.issue.title }}' | jq ...

# 안전 방향: 데이터 경계를 유지한다
env:
  ISSUE_TITLE: ${{ github.event.issue.title }}
run: jq --arg title "$ISSUE_TITLE" '{title: $title}'

탐지값을 증명처럼 쓰고 있지 않은가
