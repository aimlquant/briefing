    SECTION 00 · EXECUTIVE SUMMARY

    이번 주의 질문: 더 강해진 AI를 어디서 멈출 것인가

    ONE SENTENCE모델 능력이 올라갈수록 경쟁력은 “무엇을 생성하나”에서 “언제 멈추고, 무엇을 기록하고, 어떤 신호로 책임을 증명하나”로 이동한다.

    세 개의 딥다이브는 서로 다른 층에서 같은 운영 문제를 드러낸다. OpenAI는 사이버 임계 능력 신호가 나타나자 강화학습을 약 2주 중단하고 최대 프런티어 실행을 계속 보류했다. Anthropic은 Claude 출력의 다음 단어 선택 분포에 통계 신호를 심되, 이 신호가 저자나 진실을 증명하지 않는다고 명시했다. Wiz가 분석한 Snowflake Connector PR에서는 안전한 환경 변수·구조화 파서 경로가 직접 셸 보간으로 바뀌며 비신뢰 입력과 Jira 비밀이 연결됐다.

    공통점은 안전이 선언이 아니라 자원 배분이라는 점이다. 감시는 추론 컴퓨트를 쓰고, 경보는 사람의 대기 시간을 요구하며, 워터마크는 표본 길이와 탐지 API라는 운영 조건이 필요하다. CI 안전은 생성 도구의 이름보다 입력·인터프리터·권한·비밀의 전체 경로를 추적해야 지켜진다. 따라서 이번 호는 “AI를 도입할까?”보다 “어떤 통제 계약 없이 도입하지 않을까?”를 묻는다.

    사건: 사후 차단이 아니라 능력을 키우는 입력에 게이트를 걸었다

    OpenAI는 OpenAI–Hugging Face 사건과 차기 모델 Astra의 예비 평가를 함께 언급하며, Astra가 Preparedness Framework의 Critical cybersecurity capability 임계값에 닿을 가능성이 있다고 설명했다. 회사는 배포를 염두에 둔 최신 모델의 강화학습을 약 2주 멈췄고, 계획한 가장 큰 프런티어 RL 실행은 작은 규모의 훈련·평가로 정렬 근거와 안전장치를 더 확인하는 동안 계속 보류한다고 밝혔다.

    이 결정의 의미는 “모델을 내놓은 뒤 위험 요청을 거부한다”와 다르다. 능력 상승의 직접 입력인 학습 자체를 멈췄다. 따라서 안전 평가는 모델 카드의 보고 항목이 아니라 연구 클러스터의 작업 승인, 네트워크 격리, 실행 용량과 출시 일정의 선행 조건이 된다.

    메커니즘: 격리, 토큰 감시, 사람의 중단 권한이 한 체인이다

    첫 번째 층은 보안 경계다. 모델 생성 코드나 비신뢰 코드를 실행하는 워크로드를 더 강한 샌드박스에 두고, 고위험 워크로드의 인터넷 접근을 분리하며, 공유 서비스와 상시 권한을 줄인다. 두 번째 층은 모니터링이다. 모든 샘플 토큰에서 활성화 분류기를 돌리고, 의심 신호를 더 비싼 자동 조사기로 넘겨 도구 행동과 전체 활동 순서를 검사한다. 세 번째 층은 사람이다. 중대한 경계 위반 가능성이 뜨면 안전·보안·연구팀이 호출되고, 30분 안에 오탐이라고 확정하지 못하면 활동을 멈추는 운영 약속이 붙는다.

    DEEP 02 · PROVENANCE · SCORE 94 · 08.14 발표 / 08.15 재부상

    Claude 워터마크는 저자를 찍는 표식이 아니라 선택 분포의 통계다

    복사·붙여넣기 뒤에도 남을 수 있지만 짧은 답·정답 제약·코드·재작성에는 약하다. 양성은 “Claude가 관여했을 가능성”이지 저자·진실·부정행위의 판결이 아니다.

    메커니즘: 숨은 문자나 추가 토큰이 아니라 난수의 출처를 바꾼다

    언어 모델은 다음 단어 후보 가운데 의미와 품질 차이가 거의 없는 여러 선택지를 만난다. Anthropic 설명에 따르면 워터마크는 임의 난수 대신 비밀 키와 앞선 단어를 사용해 이 낮은 위험의 선택을 결정한다. 독자는 차이를 느끼지 못하지만 긴 문장 전체에서 같은 키와 일관된 선택 패턴이 누적되면 탐지기가 Claude 관여 확률을 계산할 수 있다. 숨은 유니코드, 사용자·조직·대화 식별자, 추가 토큰을 넣는 방식이 아니다.

    Anthropic은 Google DeepMind가 2024년 Nature 논문으로 발표한 SynthID-Text 계열을 사용한다고 밝혔다. 회사 내부 시험과 SynthID 연구에서는 품질 차이가 통계적으로 유의하지 않았다고 보고했지만, 이것은 공개 탐지 API의 실제 임계값과 현장 오탐률을 대신하지 않는다. API는 “곧 제공”할 계획이라고만 공개됐다.

    한계: 선택지가 적을수록 신호를 심을 공간도 줄어든다

    “2 + 2 =”의 다음 답이나 고유명사, 정확한 코드 토큰처럼 정답 제약이 강한 위치에서는 다른 단어를 고르면 품질이 무너진다. 따라서 워터마크는 사실 중심 문장, 교정, 짧은 응답, 코드에 상대적으로 희박하다. 인간 글을 조금 교정한 경우에도 Claude가 고른 단어 자체가 적어 탐지가 어려울 수 있다. 번역처럼 대부분의 단어를 Claude가 다시 고르는 작업은 반대로 신호 공간이 넓다.

    편집 공격도 중요하다. Anthropic은 가벼운 수정은 신호를 완전히 없애지 못할 수 있지만 모든 단어를 바꾸는 전면 재작성은 제거할 수 있다고 썼다. 양성은 Claude가 어느 시점에 텍스트를 생성하거나 크게 편집했을 가능성을 뜻할 뿐, “Claude가 전부 썼다”와 “Claude가 크게 편집했다”를 구분하지 못한다. 음성도 Claude를 사용하지 않았다는 보장이 아니다.

    DEEP 03 · SUPPLY CHAIN · SCORE 97

    AI 보조 PR에서 안전한 데이터 경계가 한 줄의 셸 코드로 무너졌다

    Copilot Autofix는 같은 PR의 별도 수정에 기여했지만 취약한 줄의 직접 저자로 확인되지는 않았다. 사고의 핵심은 사람·도구가 함께 승인한 PR 전체에서 비신뢰 입력, 셸, 장기 비밀의 연결을 놓친 것이다.

    06.18취약 PR 병합06.23발견·신고·수정08.17Wiz 공개0건Wiz 외 악용 확인 없음

    사건: env와 jq로 전달하던 이슈 제목이 run 블록 안으로 들어갔다

    Wiz Red Agent는 snowflakedb/snowflake-connector-net의 jira_issue.yml을 분석했다. 기존 코드는 이슈 제목을 env: ISSUE_TITLE로 넘기고 jq --arg로 JSON에 삽입했다. 병합된 변경은 이 경계를 제거하고 ${{ github.event.issue.title }}을 run: 셸 블록 안의 작은따옴표 문자열에 직접 확장했다. 워크플로는 누구나 열 수 있는 이슈의 opened 이벤트로 실행됐으므로 공격자는 제목으로 따옴표를 닫고 임의 명령을 실행할 수 있었다.

    귀속은 정확히 제한해야 한다. Wiz 원문은 Copilot Autofix가 같은 PR의 jira_close.yml에 별도 수정으로 공동 기여했다고 설명한다. 취약한 jira_issue.yml 줄을 Autofix가 직접 만들었다는 증거는 아니다. 그러나 AI 보조가 표시된 PR이 최종적으로 안전한 패턴을 제거했고 GitHub Advanced Security가 최종 워크플로를 분석하고도 주입을 잡지 못했다는 점은 그대로 남는다.

    공격 경로: 템플릿 확장 뒤의 escaping은 너무 늦다

    GitHub 표현식은 셸이 실행되기 전에 값으로 치환된다. 따라서 sed로 따옴표를 이스케이프하는 코드가 있더라도, 이미 공격자 문자열이 셸 소스 코드 안에 들어온 뒤다. 공격자는 첫 실행의 구문 오류를 관찰하고 페이로드를 수정해 Jira 자격증명을 외부 콜백으로 보냈다. Wiz는 6월 23일 신고 당일 수정과 토큰 교체가 이뤄졌고 감사 로그상 Wiz 외 악용은 없었다고 보고했다.
